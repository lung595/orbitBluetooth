# Audit, November 2026

Security, performance and code quality pass over the plugin, run as a
time-boxed loop on 2026-11-12 (17:57 to 19:27), then a second loop the same evening (21:10 to 21:55) for what was left. Each fix was made on its own
local branch `audit/<slug>` from `main`. All of them were merged into `main`
the same night, reviewed again after the merge (see *Pre-release review*), and
released in **2.1.0**.

Scope: QML/JS (`components/`, root `*.qml`, `diagnostics/`, `shaders/`),
the ANC daemon (`anc/`), `uninstall/`, `graph/`, `scripts/`.
Out of scope: the tests themselves.

Baseline before any change: ANC 62 tests OK, uninstall 17 OK (run from
`uninstall/`: `(cd uninstall && python3 -m unittest discover -s tests -t .)`),
QML all passed, gjs 2621 passed.

## Pre-release review

After the merge, a review of `main` against 2.0.0 (one finder per area, each
finding then checked by an independent agent that tried to refute it) found
these before anything was pushed. One more claim, that the changelog's SDP
depth was wrong, was refuted: the old parser did crash at about 1 000 levels.

| Sev. | Where | What | Status |
|------|-------|------|--------|
| Major (regression) | `uninstall/orbit_uninstall.py` `edit()` | Writing through a link (`audit/uninstall-symlink`) made a link into a read-only folder (home-manager's `/nix/store`) fail in `mkstemp`, outside the `try`: the sweep stopped there and the volume keys stayed bound to the removed plugin. | fixed: that file is left as it is, the sweep goes on (test with a link into a read-only folder) |
| Minor (regression) | `components/pairing/ProfileCheck.qml` | The queue (`audit/profile-check-queue`) held devices in a plain JS array: a device destroyed during its check was a truthy dead wrapper, so `forget()` threw and the verdict never came. A `busctl` that could not start left its job at the head for good, so no later pairing was ever checked. | fixed: `ToolProcess` (`finished(-1)` when it cannot start), the next check always runs, a dead device is *refused* without touching it |
| Minor | `components/scene/HoldRing.qml`, pointers | The hold's Timer looks every 33 ms, so a release past 500 ms but before the next tick was a click: nothing on a device, *accept* instead of *decline* on a suggested group. | fixed: `HoldRing.settle()` on release, in the three pointers |
| Minor | `scripts/diagnose.sh` | The journal is printed in the user's locale (`nov. 12`), which the host-column rule (English months) does not match. | fixed: `LC_ALL=C journalctl` |

## Checked and clean

- Command injection: every process is an argv list; data reaches `sh`/`bash` only as positional `$1..$3`; `Keys.js` clamps steps and fixes verbs; the loopback `q()` escape holds against hostile values (tested); `ScopeFeed` names are shape-checked.
- Uninstall paths: plugin id regex, absolute paths, cache folder named after the plugin, `rmtree` refuses links, the loopback link is removed only when it is exactly Orbit's.
- The other ANC parsers (Apple, Bose, EarFun, Haylou, Moondrop, 1MORE, Oppo, Samsung, Huawei params, Sony frame decode): indexes guarded, loops always advance.
- Performance: OrbitPhysics, RadarClock, HoldRing, PolarScope, ScopeModel, Starfield, ChargeBeam/EnergyBeam and OrbitDaemonData timers are all gated; FrozenBlur is `live: false`; Loaders gated; canvases repaint only on change; no polling process; `orbit_anc.py` select has no busy loop.
- Network: none. Logging: only `Log.js` codes through `Redact.text`. Sockets closed in `finally`; the helper leaves when stdin closes.

## Left for the owner

- `diagnostics/Gather.js` `wl-copy --sensitive` keeps serving the copied report after the shell exits (that is how a Wayland copy works). It bends "no process outlives the shell"; accept it or say so in the README privacy section.
- `components/battery/BatterySessions.js`: the salt sits in the same `history.json` as the hashes, so the hash stops cross-file linking but not identification (~2^24 guesses with a known vendor prefix). Nothing runs it yet (logic only); decide before wiring it, and the cache file is outside "memory or DMS's settings".
